## 实现清单

### 按住说话链路

`app/src/main/java/com/dshgojava/assist/platform/OverlayBall.java`

- 在 QA01 复制版上增加 `setHoldReleaseListener(release, cancel)`：原有 `onStop`
  只通知长按触发，无法区分松手与取消；语音必须拿到后续触摸边缘。
- `fire()` 仍由长按计时器触发；`ACTION_UP` 调用 release，`ACTION_CANCEL` 与
  `detach()` 调用 cancel。若松手恰好落在长按阈值边界而没有实际触发捕获，
  不再补发 start，避免录音会话泄漏。

`app/src/main/java/com/dshgojava/assist/ui/AssistBall.java`

- `Listener` 新增 `onLongPressEnd(boolean cancelled)`，并把平台层 release/cancel
  转发给前台服务。

`app/src/main/java/com/dshgojava/assist/voice/SystemVoiceCapture.java`

- `VoiceCapture` 的 Android 实现：使用系统 `SpeechRecognizer`，语言取系统 Locale，
  开启 partial results；麦克风音频完全由系统识别引擎处理，本类不落盘。
- 松手调用 `stopListening()`；若 6 秒内没有 final/error，则取消并显示
  「语音转写超时，请重试」，不会一直停在转写状态。
- 识别器回调按 generation 过滤，`cancel()`/`release()` 后晚到的结果不会进入 UI。
- 所有 `SpeechRecognizer` 创建、监听和销毁均在主线程执行。

`app/src/main/java/com/dshgojava/assist/voice/VoiceCapture.java`

- Android-free 的语音捕获边界，便于 JUnit 注入假实现；提供 partial/final/error
  三种回调与 stop/cancel/release 生命周期。

`app/src/main/java/com/dshgojava/assist/voice/VoicePolicy.java`

- 纯逻辑判定「无引擎」优先于「无麦克风权限」，避免把不可修复的引擎缺失误报成权限问题。
- 统一转写文本去首尾空白与不换行空格；映射 `SpeechRecognizer` 公共错误码，
  包含无语音、无匹配、引擎忙、网络、超时、语言不支持等明确文案。

`app/src/main/java/com/dshgojava/assist/source/VoiceSource.java`

- 实现 `AssistSource`，`kind=VOICE`；封装捕获开始/停止/取消与一次性转写结果。
- final 文本保存在线程安全的一次性槽位；`gather()` 优先使用
  `VoiceSource.CONTEXT_TEXT`，其次消费已保存文本，并返回
  `source=voice / engine=system / chars=N` 元数据。
- 转写为空时返回 `CaptureException`，不会构造空 `CaptureBundle` 或假装成功。

`app/src/main/java/com/dshgojava/assist/ui/AssistVoiceHud.java`

- 不可触摸的底部状态胶囊：录音时显示「正在录音… 松手转写」及 partial 文本，
  松手后显示「正在转写…」，失败时红色提示并在 3 秒后自动消失。
- 若悬浮窗添加失败，调用方回退到 Toast；窗口异常不会造成静默无响应。

### 服务与任务接入

`app/src/main/java/com/dshgojava/assist/service/AssistOverlayService.java`

- 创建并注册 `VoiceSource`；`SCREEN/CLIP/IMAGE/VOICE` 均可由同一个
  `DefaultAssistRunner` 调度。
- 长按依次检查：语音引擎 → 麦克风权限 → 模型连接；任一不满足都给出明确提示，

### 线程与隐私

- `SpeechRecognizer` 生命周期在主线；`VoiceSource.gather()` 使用的文本封装与元数据
  构造在单线程执行器，不占用主线程。
- 不保存音频文件，不把转写写入日志；HUD 仅在当前录音期间临时显示 partial 文本，
  完成后的结果是否进入历史仍由既有 `AssistHistoryStore` 决定。

## 与设计文档的差异

1. **转写实现选择系统 SpeechRecognizer，而不是复制 `WavRecorder`。**
   设计把语音录制列为可复用能力，但本应用没有 dsh-Go-java 的本地语音模型、
   `MicArbiter`、诊断桥与 WAV 上传通道。系统识别器自身拥有麦克风音频，直接给出
   partial/final 文本；若先复制 `WavRecorder` 再找后端，会引入没有消费者的死代码。
   因此本任务采用 `VoiceCapture → SystemVoiceCapture`，不落盘音频，也不新增音频
   API 配置。
2. **长按入口不进二级菜单。** 设计的一级菜单仍是四组（屏幕/网页/文本/图片），
   语音是悬浮球长按快捷入口；`voice.transcribe` 只注册为可调度任务，不出现在四组
   菜单中，避免凭空增加设计未规定的第五组。
3. **`voice.transcribe` 仍走一次模型调用。** 当前 `AssistRunner` 的统一契约是
   「取料 → 拼提示 → 模型 → 卡片」；系统转写作为取料文本，模型只做同音字、标点与
   断句整理。原始转写不直接展示，避免与既有卡片状态机形成第二条执行路径。
4. **给复制版 `OverlayBall` 增加 release/cancel 回调。** 这是按住说话必需的本地扩展，
   不是上游缺陷；参考仓库未做任何修改。
