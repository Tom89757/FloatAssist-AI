## 实现清单

### 调度接口与状态容器

`app/src/main/java/com/dshgojava/assist/AssistRunner.java`

- 保留设计文档 §5 的 `AssistRunner.start(QuickTask, AssistRequest)`。
- `AssistRun` 暴露 `StateStore<AssistResult> state()`、`cancel()` 与 `close()`。
- `close()` 在运行未结束时等价于 `cancel()`；已完成/失败/取消后为幂等空操作，不会把 `DONE` 覆盖成 `CANCELLED`。

`app/src/main/java/com/dshgojava/assist/StateStore.java`

- 按设计文档 §12 的“极简版，观察者 + 快照”自建，未从参考仓库复制。
- `state()` 返回当前不可变快照；`subscribe(...)` 立即投递一次当前快照并返回取消订阅的 `Runnable`。
- 通知使用 `CopyOnWriteArrayList`，允许在回调中取消订阅；通知线程是状态发布线程，Android 视图层必须先 `post()` 到主线程。

### DefaultAssistRunner

`app/src/main/java/com/dshgojava/assist/DefaultAssistRunner.java`

构造接缝：

- `DefaultAssistRunner(ModelChannel, Map<SourceKind, AssistSource>)`：按取料源注入，供 QA05/QA07 装配。
- `DefaultAssistRunner(ModelChannel, Function<SourceKind, AssistSource>)`：保留按需查找能力，便于测试和后续惰性装配。

一次运行的完整顺序：

1. 校验 `request.task().id()` 与 `start(...)` 的 `task.id()` 一致；不一致时立即 `FAILED`，文案“请求与任务不匹配”，不取料、不调模型。
2. 查找任务对应的 `AssistSource`；缺失或 `available()==false` 时通过 `TaskPreflight.beforeStart(...)` 明确失败。
3. 检查 `ModelChannel.ready()`；未配置时立即 `FAILED`，文案“未配置模型”。
4. 检查 `needsVision` 与 `ModelChannel.supportsVision()`；不支持读图时立即 `FAILED`，文案“当前模型不支持读图”。
5. 发布 `GATHERING`，只调用一次 `AssistSource.gather(request)`。
6. 取料完成后再执行 `TaskPreflight.afterCapture(...)`；空文本或视觉任务缺图时明确失败。
7. 用 `PromptTemplate.fill(task, ...)` 填充 `{{text}}`，发布 `THINKING`，只调用一次 `ModelChannel.complete(...)`。
8. `onDelta` 累积增量并发布 `STREAMING` 快照；最终 future 返回的非空完整文本优先，没有完整文本时使用已累积流。
9. 模型正常结束且文本非空时发布 `DONE`；空响应显式失败为“模型返回为空”。
10. 取料或模型 future 异常时发布 `FAILED`；网络失败、视觉不支持、来源不可用等均保留明确文案，不做静默降级。

提示词文本规则：

- 取料文本非空时，`{{text}}` 使用 `CaptureBundle.text()`。
- 取料文本为空时（典型为 `ImageSource` 的图片任务），使用 `AssistRequest.userInput()`；否则图片任务中用户在 prompt 模板里预留的“用户补充”位置会永远为空。
- 图片仍通过 `CaptureBundle.images()` 原样传给模型通道，不拼进字符串提示词。

取消与竞态：

- `cancel()` 把状态原子切到 `CANCELLED`，并取消当前记录的取料或模型 `CompletableFuture`。
- 取料和模型调用都在同一个运行锁内进入，避免取消与启动之间无条件启动后一阶段。
- 取消后到达的 `onDelta`、取料完成、模型完成、异常回调都检查终态并忽略，不覆盖 `CANCELLED`。
- `AssistResult.cancelled()` 沿用既有空文本快照；部分流式文本只在 `STREAMING` 阶段可见，取消后不保留。

错误与线程：

- `CaptureException` 与 `ModelException` 的用户文案直接进入 `AssistResult.error`；未知异常的文案统一为“任务执行失败”，避免把内部细节或凭据带入卡片。
- 调度器本身不做截图、文件 IO 或阻塞网络请求；`ScreenSource`/`ClipSource`/`ImageSource` 在自己的后台执行器取料，`DirectApiModelChannel` 在 OkHttp 异步回调中流式返回。
- `StateStore` 不强制线程切换；QA06 卡片按设计 §8.4 在监听器中主线程序列化刷新。

## 与设计文档的差异

1. **`StateStore` 包名**：设计文档 §5 写的是 `com.dshgojava.app.state.StateStore<AssistResult>`，这是参考仓库命名空间。本仓库硬性命名空间为 `com.dshgojava.assist`，因此实际类型为 `com.dshgojava.assist.StateStore<AssistResult>`；字段与方法保持 `state()` / `subscribe(...)` / `setState(...)` 的观察者契约。
2. **`StateStore` 未复制**：设计文档 §12 明确将其列在“本仓库自建（不复制）”；本实现只读取参考仓库真实源码确认签名与单向状态流语义，没有新增 `assist/platform/` 文件。
3. **用户补充的填充时机**：设计文档只规定 `{{text}}` 与取料文本，没有说明 `AssistRequest.userInput` 如何进入提示词。本实现仅在取料文本为空时作为占位符内容，避免把同一个附加说明重复拼进已有屏幕/剪贴板文本；图片任务仍由图片载荷承载。
4. **任务不一致的显式失败**：设计文档允许 `start(task, request)` 同时接收任务和请求，但未规定冲突。本实现比较任务 id，冲突时立即 `FAILED`，避免用 A 任务模板读取 B 任务请求。
5. **取消结果不保留部分文本**：既有 `AssistResult.cancelled()` 是空文本快照，本任务沿用数据契约；取消失败/成功都不可被迟到回调覆盖。
6. **构造器扩展**：设计文档只给出接口，未规定实现注入方式。本实现增加 `Map` 与 `Function` 两种只读接缝，不改变 `AssistRunner` 公共接口。
7. **不在本任务实现重试**：调度器只执行一次取料和一次模型调用；网络失败只进入 `FAILED`。按设计 §9，QA06 如需“只重试模型、不重新取料”，需要自行保留取料产物或增加模型重试接缝，不能直接调用 `start(...)` 重跑整条链。
8. **结构化动作**：`AssistResult.actions` 本任务固定为空列表，地址/时间/电话抽取及动作按钮属于 QA10。
