## 实现清单

### 四条任务路由

`TaskRegistry` 中已有的 P0 四条任务全部走同一条
`AssistSource.gather → DefaultAssistRunner → ModelChannel → AssistCardLayer` 链路：

| 任务 ID | 输出 | 取料 | 视觉 | 本任务补的链路 |
| --- | --- | --- | --- | --- |
| `clip.summarize` | `TEXT_CARD` | `ClipSource` | 否 | 前台剪贴板桥接 → 服务分发 → 卡片流式结果 |
| `clip.polish` | `TEXT_CARD` | `ClipSource` | 否 | 同上 |
| `image.ocr` | `COPY_TEXT` | `ImageSource` | 是 | 图片选择/分享 → 私有缓存 → 服务分发 → 复制型结果卡片 |

任务选择仍由 `AssistBall.Listener.onTaskSelected` 触发；结果卡片继续复用 QA06 的流式、
复制、分享和单轮追问能力。

### ClipSource 与前台剪贴板桥接

`app/src/main/java/com/dshgojava/assist/source/ClipSource.java`

- 保留读取 `ClipboardManager.getPrimaryClip()` 的原始路径，所有读取仍在
  `assist-clipboard` 单线程执行器上完成。
- 新增 `CONTEXT_TEXT = "clip_text"`：服务收到前台 Activity 已捕获的文本时优先使用该值，
  避免 Android 10+ 在服务退到后台后拒绝剪贴板读取。
- 桥接文本与直接读取复用 `ClipText.join(...)`：统一换行、去重、去首尾空白，并继续限制
  100,000 字符；空文本显式失败，不调用模型。
- 新增 `close()`，服务销毁时关闭执行器；执行器已停止时返回“剪贴板读取已停止”的明确失败。

`app/src/main/java/com/dshgojava/assist/ui/AssistCaptureActivity.java`

- 透明、无标题的取料 Activity；剪贴板模式在窗口获得焦点后启动后台读取，满足 Android
  10+ “仅前台应用可读剪贴板”的限制。
- 成功时把文本放入显式服务 Intent（`ACTION_CLIP_TEXT`），随后立即结束；文本不写日志、
  不落盘、不进入历史。
- 剪贴板为空、系统拒绝读取、无系统选择器等均 Toast 明确提示，不伪造成功结果。

### ImageSource 与图片选择/分享

`app/src/main/java/com/dshgojava/assist/source/ImageSource.java`

- 保留 `select(Uri)` / `clearSelection()` / `gather(...)`；`available()` 只在已选图片时为真。
- `gather(...)` 支持请求上下文 `image_uri`，空白 URI 视为未选择；读取、32 MB 上限检查、
  JPEG 降采样（长边 1024）全部在 `assist-image` 执行器上完成。
- 新增 `close()`，服务销毁时清空选择并关闭执行器。

`AssistCaptureActivity` 的图片路径：

- 内部入口使用 `ACTION_OPEN_DOCUMENT + CATEGORY_OPENABLE + image/*` 调用系统选择器；
  没有图片选择器时明确提示。
- 图片先在后台上限 32 MB 复制到私有缓存 `cache/assist-capture/image-*.img`，再把
  `file://` URI 交给服务。这样不依赖分享 URI 在 Activity 结束后仍然有效。
- 对外注册 `ACTION_SEND + image/*` 分享目标，弹出“图片取字 / 图片解说”二选一；多图
  分享只处理第一张并明确提示。分享入口需要用户二次选择任务，不会静默消耗模型调用。
- 缓存仅在服务正常启动/销毁时清理，属本机临时数据，不进入历史、不上传。

### 服务分发与前置判断

`app/src/main/java/com/dshgojava/assist/service/AssistOverlayService.java`

- `onTaskSelected` 对剪贴板任务启动前台桥接；对未选图片的图片任务启动系统选择器；
  其余任务直接进入调度器。
- 处理 `ACTION_CLIP_TEXT` 与 `ACTION_IMAGE_SELECTED`，校验任务 ID、来源类型和图片 URI；
  校验失败显式 Toast，不启动假任务。
- 新任务统一进入 `startTask(...)`，保留 `ModelRetry` 接缝，结果继续由 `AssistCardLayer`
  展示。
- 服务销毁时关闭屏幕、剪贴板、图片三个取料执行器并清理图片缓存。

`app/src/main/java/com/dshgojava/assist/ui/AssistGate.java`

- 新增纯 Java 前置条件投影，服务菜单和测试共用。
- 顺序：屏幕无障碍 → 模型已连接 → 视觉能力 → 剪贴板服务 / 已选图片。这样图片组在
  “未连接模型”或“模型不支持视觉”时不会先诱导用户选图。

`app/src/main/java/com/dshgojava/assist/ui/AssistCardView.java`

- `GATHERING` 状态按任务来源显示“正在读取剪贴板…”或“正在读取所选图片…”，不再统一显示
  “正在读取屏幕…”。

## 与设计文档的差异

1. **剪贴板需要前台桥接 Activity**：设计 §4/§8.4 只要求 `ClipSource` 读剪贴板，未说明
   Android 10+ 的后台读取限制。若服务直接读取，悬浮球场景下系统通常返回空值。本实现增加
   透明 `AssistCaptureActivity`，在窗口焦点内读取后把文本交给服务；这是设计文档未列出的
   文件与交互，但避免了“看似可用、实际永远为空”的静默失败。
2. **图片先复制到私有缓存**：设计让 `ImageSource` 直接读选中的 URI。`ACTION_SEND` 的读取
   授权通常只覆盖接收 Activity 生命周期，服务异步降采样时可能已失效。本实现先在 Activity
   后台复制（≤32 MB）到应用缓存，再让 `ImageSource` 读文件 URI；缓存为本地临时数据并在
   服务正常启动/销毁时清理。
3. **分享入口**：设计 §3 提到 `ImageSource` 支持“分享”。本实现增加对外 `ACTION_SEND
   image/*` Activity 和一个二选一任务对话框；未实现 `ACTION_SEND_MULTIPLE` 多图批量处理，
   收到多图时明确提示只处理第一张。
4. **最近截图未单列**：设计 §3 提到“最近截图”。本任务使用系统文件/相册选择器，用户可直接
   选择截图；未单独查询 MediaStore 最近截图，因为 Android 13+ 需要额外媒体读取权限，留待
   后续任务评估。这是本次相对设计文档的功能缺口，已在此登记。
5. **菜单门禁顺序**：设计 §9 只列单场景行为，未规定组合优先级。本实现先报屏幕无障碍，
   再报模型/视觉，最后报剪贴板服务或未选图片；保证用户先处理更根本的设置问题。
6. **空剪贴板不做菜单级预检**：菜单只能判断剪贴板服务是否存在，不能在后台读取内容（同样的
   Android 10+ 限制）。用户点击后才由前台桥接发现空剪贴板并 Toast 提示，不会调用模型。
7. **模型通道仍为 `NullModelChannel`**：与 QA05–QA07 一致，真实 `DirectApiModelChannel`
   与设置页连接属于 QA09。本任务用注入的假模型验证了四条任务端到端状态机；真机上在
   QA09 完成前任务入口仍会灰显“未连接”，不会假装执行。
