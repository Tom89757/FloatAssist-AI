## 实现清单

### AssistPrefs：私有模型配置

`app/src/main/java/com/dshgojava/assist/store/AssistPrefs.java`

- 使用 `Context.MODE_PRIVATE` 的 `quick_assist_prefs`，不新增依赖，也不把凭据写入日志、
  历史或页面回显。
- 保存：悬浮助手开关、用途说明已读标记、默认通道（固定 `direct`）、接口地址、API key、
  模型名、是否支持视觉。
- `Snapshot` 暴露 `overlayEnabled`、`noticeSeen`、`channel`、`DirectApiModelChannel.Config`
  与 `hasApiKey`；`Snapshot.toString()` 通过 `Config.toString()` 把 key 脱敏为 `<redacted>`。
- API key 只由服务读取用于构造模型通道；设置页只读取“是否已保存”，输入框始终不回填密钥。
  留空保存会保留原密钥，清除密钥必须使用独立的“清除 API key”按钮。
- API key 输入框关闭 Android 的 View 状态保存，避免旋转/进程重建时把用户刚输入的密钥写进
  Activity instance state。
- 读、写都由调用方的后台单线程执行器完成，主线程只更新 View。

### AssistHistoryStore：本地历史

`app/src/main/java/com/dshgojava/assist/store/AssistHistoryEntry.java`

- 历史项只含 `id`、时间、任务 ID、任务标题、回答文本、是否追问，不保存截图、取料原文、
  提示词、模型配置或 API key。
- 文本上限 100,000 字符；任务标识与文本为空时拒绝写入。

`app/src/main/java/com/dshgojava/assist/store/AssistHistoryStore.java`

- 文件位置：应用私有目录 `files/assist/history.json`，UTF-8 JSON，格式版本 `1`。
- 最多保留 200 条，按时间新到旧返回；写入先写 `.tmp` 再原子替换，替换失败时回退内存快照。
- 支持按条删除、一键清空；文件缺失、版本不符或 JSON 损坏都按空历史处理，之后可正常覆盖写入。
- 进程内共享同一实例，悬浮服务与设置页看到同一份缓存；所有公开读写方法同步执行，调用方负责
  离开主线程。

### 设置页与权限引导

`app/src/main/java/com/dshgojava/assist/ui/AssistSettingsActivity.java`

- 原生 `Activity + XML` 设置页，并注册为应用启动入口；运行通知也改为打开此页。
- 首屏展示用途与隐私说明；首次启动弹出不可取消的用途说明，确认后写入 `noticeSeen`。
- 悬浮助手开关：
  - 无悬浮窗权限时明确提示并打开 `Settings.ACTION_MANAGE_OVERLAY_PERMISSION`；
  - 返回并授权后自动继续开启；
  - 启动失败会回写开关为关闭并显示失败文案；
  - 已保存为开启且权限仍在时，重新进入设置页会恢复运行。
- 权限引导包含悬浮窗、无障碍、通知三项及实时状态；无障碍打开
  `A11yBridge.accessibilitySettings()`，通知在 Android 13+ 请求 `POST_NOTIFICATIONS`，
  否则打开系统通知设置。
- 模型区包含接口地址、模型名、API key、视觉能力开关、保存与清除密钥；缺失字段时任务入口
  继续灰显，并显示“未连接”的明确文案。
- 历史区按新到旧列出任务、摘要、时间；点击查看全文，可按条删除、确认后一键清空。历史读写、
  清空全部在 `assist-settings` 单线程执行器执行。

`app/src/main/res/layout/activity_assist_settings.xml`

- 原生 View 布局，无第三方 UI 库；包含设置、模型表单与可滚动历史列表容器。

## 与设计文档的差异

1. **API key 存储方式**：设计允许 `EncryptedSharedPreferences` 或“私有目录文件 +
   `MODE_PRIVATE`”。本任务选择后者中的 `SharedPreferences(MODE_PRIVATE)`，避免新增
   `androidx.security` 依赖；密钥不出日志、不回显、不进历史，应用已声明 `allowBackup=false`。
2. **`AssistPrefs` 的球位置字段**：设计文件清单写到“开关、默认通道、球位置”。本仓库现有
   `OverlayBall` 已经通过 `OverlayPrefs` 的 `ballSide`/`ballY` 持久化位置，QA09 不重复存储，
   避免两个事实来源冲突；`AssistPrefs` 负责开关、说明已读、通道与模型配置。
3. **设置入口**：设计只写“设置页新增入口”，但仓库此前没有主 Activity。QA09 新增
   `AssistSettingsActivity` 作为桌面入口，并同时在悬浮菜单与运行通知中提供入口。
4. **历史内容**：设计只规定 JSON、最多 200 条、仅本地、可删除。本任务按隐私最小化只保存
   任务信息与最终回答，不保存截图/取料原文；失败与取消不进入历史。
5. **首启说明**：设计 §10 要求首次启动展示用途说明。本任务在设置页首启弹窗实现，并由
   `noticeSeen` 持久化，授权开关与隐私说明同页可见。
6. **配置热更新**：设计未规定设置修改后的行为。本任务新增 `ACTION_RELOAD`；为避免旧通道
   继续处理追问，重建调度器时会关闭当前结果卡片，而不是混合新旧配置。
7. **通知权限**：Android 13+ 只在用户开启悬浮助手时请求 `POST_NOTIFICATIONS`；拒绝不会伪造
   成功状态，设置页会明确显示通知“未开启”。
8. **模型校验**：设置页只校验接口地址的 `http://`/`https://` 前缀与字段完整性；真实 URL、
   鉴权与模型可用性仍由 `DirectApiModelChannel` 在调用时显式失败，不在保存时假装连通。
