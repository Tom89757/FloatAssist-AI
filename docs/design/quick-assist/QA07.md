## 实现清单

### 四个屏幕任务的路由

四个任务均已在 `TaskRegistry` 注册为 `SourceKind.SCREEN`，由 `AssistOverlayService` 的同一份取料源映射路由到 `ScreenSource`：

| 任务 ID | 标题 | 输出 | 视觉要求 | 端到端路径 |
| --- | --- | --- | --- | --- |
| `screen.summarize` | 总结当前屏幕 | `TEXT_CARD` | 否 | `ScreenSource → DefaultAssistRunner → ModelChannel → AssistCardLayer` |
| `screen.extract` | 提取屏幕文字 | `COPY_TEXT` | 否 | 同上；卡片提供复制动作 |
| `screen.translate` | 翻译当前屏幕 | `TRANSLATE_CARD` | 否 | 同上 |
| `screen.what` | 这是什么 | `TEXT_CARD` | 是 | 同上；必须取得截图后调用支持视觉的模型 |

屏幕任务选择流程已经接通：`AssistBall.Listener.onTaskSelected` 启动 `DefaultAssistRunner`，结果卡片订阅同一 run 的状态流并流式展示。无无障碍时屏幕组在菜单中灰显，点击进入系统无障碍设置，不会发起假任务。

### ScreenSource 取料

`app/src/main/java/com/dshgojava/assist/source/ScreenSource.java`

- 继续遵循设计 §8.2：先 `TreeCapture.capture(...)`；树文本少于 40 字符或任务 `needsVision=true` 时才截图。
- 树文本由 `ScreenTextExtractor` 按视觉顺序整理，过滤密码、OTP、验证码字段；对应矩形在截图前作为遮罩输入。
- 截图由 `ScreenShooter` 完成，长边超过 1024 时由 `ImageDownsampler` 降采样，再作为 `PromptImage` 传给模型。
- 安全窗口、Android 11 以下截图、全黑截图、截图解析失败均有明确错误；需要视觉但拿不到截图时任务失败，不假装运行。
- 增加 `close()`，前台服务销毁时关闭屏幕取料执行器，避免服务停止后留下常驻线程。

### 截图隐藏悬浮层

设计 §8.1 要求截图前隐藏悬浮球。QA01 复制的 `ScreenShooter` 只保留 `CaptureVisibility` 计数，而本仓库的球和结果卡片是独立窗口；QA07 因此在服务层补了实际的窗口隐藏协调：

- `A11yBridge` 新增 `CaptureOverlay` 注册点与 `setCaptureOverlayHidden(boolean)`：从后台截图线程把隐藏/恢复操作同步投递到主线程，1 秒内未完成则明确拒绝截图。
- `AssistOverlayService` 在 `onCreate` 注册协调器，同时隐藏 `AssistBall` 与其菜单、`AssistCardLayer` 的结果卡片；`onDestroy` 注销。
- `AssistBall.setHiddenForCapture(...)` 隐藏球根视图、暂停 idle 动画和菜单展开；恢复后重新唤醒球。
- `AssistCardLayer.setHiddenForCapture(...)` 隐藏骨架/流式卡片；若卡片在截图期间才创建，也会按当前隐藏状态以 `INVISIBLE` 挂载。
- `ScreenSource` 在截图前后成对调用隐藏/恢复，并在 `finally` 中恢复，异常路径不会把悬浮层留在隐藏状态。隐藏后等待 48 ms 让窗口合成完成。

### 提示词与模型请求

- 为摘要、提字、翻译三条提示词补充“若随附截图，请结合截图”的约束，使树文本较短时模型明确知道截图是补充证据。
- 调度器只把图片发给声明支持视觉的模型。非视觉屏幕任务即使因树文本较短而附带截图，也不会把不支持的图片载荷发送给模型。
- `screen.what` 仍在启动前检查模型视觉能力；不支持时立即失败为“当前模型不支持读图”，不取料、不调用模型。
- 非视觉屏幕任务在树文本为空、只有截图时不做伪视觉调用；错误文案改为“当前页面没有可读文字，请改用‘这是什么’”，提示用户改用视觉任务。

## 与设计文档的差异

1. **悬浮层隐藏实现**：设计文档只要求复用 `CaptureVisibility`。本仓库复制的 `ScreenShooter` 中该对象仅维护计数，没有观察方；QA07 保留其截图内计数，同时新增 `A11yBridge.CaptureOverlay`，让服务层真正隐藏球和结果卡片。这样也覆盖了结果卡片骨架屏，避免截图命中本应用窗口。
2. **空文本屏幕任务**：设计 §7 明确 `needsVision=false` 且文本为空时直接失败，因此不把 image-only 截图交给文本任务；仅将其改为更可执行的错误提示。这是对 QA02 通用文案“没有可处理的内容”的屏幕组细化。
3. **非视觉模型过滤**：设计未规定文本任务附带截图但模型不支持视觉时的处理。本实现保留文本路径并丢弃该截图，避免发送模型无法处理的图片。
4. **响应时间**：为保证隐藏效果，截图前固定等待 48 ms。该等待只发生在实际截图路径，树文本足够时不会触发。
5. **真实模型尚未接入**：`AssistOverlayService` 仍按 QA05/QA06 的约定注入 `NullModelChannel`，因此当前真机菜单中的任务会灰显“未配置模型”。QA09 接入 `AssistPrefs` 与 `DirectApiModelChannel` 后，四个屏幕任务才会对用户可执行；QA07 已验证其调度与 UI 接线。
6. **Local OCR**：设计 §8.2 允许截图后本地 OCR，但本仓库仍使用 `NoLocalOcr`，未把“无 OCR 引擎”伪装成识别成功。树文本不足且任务不需要视觉时按设计 §7 显式失败。
