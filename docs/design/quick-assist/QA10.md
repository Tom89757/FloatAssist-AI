### 地址、时间、电话抽取

`app/src/main/java/com/dshgojava/assist/action/ActionTime.java`

- 纯逻辑时间解析：ISO 日期/时间、`yyyy-MM-dd HH:mm`、中文年月日、月日、相对日期
  （今天/明天/后天/大后天）、中文时段（上午/下午/晚上/中午/凌晨）与纯时刻。
- 纯时刻已过时顺延到次日；日期无误时返回 `dateOnly=true`；非法日期/时刻返回 null。

`app/src/main/java/com/dshgojava/assist/action/ActionExtractor.java`

- 纯文本兜底抽取：手机号、座机、国际号码、完整/相对/月日/纯时刻，以及带标签或
  地址特征词的地址行。
- 地址行显式兼容 Unix（`\n`）与 Windows（`\r\n` 或 `\r`）换行，不在运行时依赖
  `\R` 的平台实现差异。
- 地址清理会去掉「地址/地点/位置」前缀、截断后面的电话/时间字段，并拒绝 URL、
  模板占位符与超长文本。

`app/src/main/java/com/dshgojava/assist/action/PhoneNumbers.java`

- 只接受数字、`+`、空格、括号和连字符；拒绝 `*`、`#` 等服务码；返回可放入 `tel:` 的号码。

### JSON 动作解析

`app/src/main/java/com/dshgojava/assist/action/ActionSheetParser.java`

- 支持模型返回 Markdown 代码块包裹的 JSON 对象、顶层 JSON 数组、对象内 `actions`
  数组，以及纯文本兜底。
- 顶层字段派生动作：`address` → `NAVIGATE`，`time`/`title`/`location` → `CALENDAR`，
  `phone` → `DIAL`；也接受显式 `kind` 为 `navigate` / `calendar` / `dial` / `copy` 的动作。
- 导航坐标同时存在时生成 `geo:lat,lng?q=lat,lng(name)`，否则生成
  `geo:0,0?q=encoded-address`。
- 动作按 `kind + value` 去重；相同类型已有显式动作时不再派生重复按钮。
- JSON 损坏不抛异常：保留可读文本并使用本地抽取；无摘要的结构化结果返回空文本，
  由卡片显示本地化的「未识别到可用地址、时间或电话号码」提示。

`app/src/main/java/com/dshgojava/assist/action/CalendarDraft.java`

- 校验日程标题、开始/结束时间与地点；默认时长 1 小时，全天日程默认 1 天。
- `AssistAction.CALENDAR.value` 使用紧凑 JSON：
  `{"title":...,"beginMs":...,"endMs":...,"allDay":...,"location":...}`。

### ACTION_SHEET 卡片按钮

`app/src/main/java/com/dshgojava/assist/ui/AssistCardView.java`

- 结果卡片新增独立动作行：标题、横向滚动按钮、无动作提示。
- 按钮文案优先使用模型 `label`，为空时按动作类型使用
  `assist_action_navigate/calendar/dial/copy` 资源。
- 动作来自 `AssistResult.actions()`，仅在 `DONE` 且非空时显示；`ACTION_SHEET` 任务
  `DONE` 但无动作时显示明确空结果提示，不伪造按钮。

`app/src/main/java/com/dshgojava/assist/ui/AssistCardLayer.java`

- 新增 `onAction`：复制动作复用系统剪贴板；其余动作交给 `ActionIntents` 在主线程启动。
- 动作信息不完整或无处理应用时分别 Toast 明确文案；不静默吞掉失败。

### Intent 跳转

`app/src/main/java/com/dshgojava/assist/action/ActionIntents.java`

- 纯逻辑 `Plan`：导航得到固定 geo URI，拨号得到规范化 `tel:`，日历得到
  `CalendarDraft`，复制保留文本。
- Android 侧使用固定 Intent 类型：
  - 导航：`ACTION_VIEW` + geo URI；
  - 拨号：`ACTION_DIAL` + `tel:`；
  - 日程：`ACTION_INSERT` + `CalendarContract.Events.CONTENT_URI`，写入开始/结束、
    全天标记、标题和地点；
  - 复制：不出 Intent，由卡片处理。
- 导航不接受任意 `intent:`/组件；非 geo/map/http(s) 的自由文本一律转成 geo 查询。
- 直接启动并捕获异常；`ActivityNotFoundException`、`SecurityException` 均返回
  `NO_HANDLER`，避免 `resolveActivity` 在 Android 包可见性下误报无处理者。

## 与设计文档的差异

1. **模型动作协议**：设计只规定 `ACTION_SHEET` 与「地址/时间/电话 → 动作」，未规定模型
   JSON schema。本任务固定了六字段 JSON，并兼容 `actions` 数组与纯文本兜底，便于模型波动
   时仍能工作。
2. **动作载荷**：设计未规定 `AssistAction.value` 的具体编码。本任务约定：
   `NAVIGATE` 为 geo/map URI，`CALENDAR` 为 `CalendarDraft` JSON，`DIAL` 为规范化号码，
   `COPY` 为原文。
3. **动作面板形态**：设计写「卡片追加动作按钮」。本任务在结果卡片内部新增动作行，
   不另开悬浮窗口，避免多个 overlay 的层级、IME 与旋转同步问题。
4. **本地兜底**：设计强调模型抽取；本任务额外加入确定性的地址/时间/电话兜底，
   用于模型返回纯文本或 JSON 损坏时仍能显式给出按钮，不假装成功。
5. **动作安全边界**：设计未列允许的 URI scheme。本任务只允许 geo、高德、百度、http(s)
   导航 URI；任意 `intent:` 等值会被转成 geo 搜索。拨号拒绝服务码。
6. **任务全集**：`TaskRegistry.all()` 现为 P0 + P1；`p0()` 保持八条，菜单使用 `all()`。
