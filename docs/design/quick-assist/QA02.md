## 实现清单

### P0 任务注册表

`TaskRegistry` 是唯一 P0 任务入口，固定 8 条声明，顺序与设计文档 §7 一致：

| id | 标题 | source | output | needsVision |
| --- | --- | --- | --- | --- |
| `screen.summarize` | 总结当前屏幕 | `SCREEN` | `TEXT_CARD` | false |
| `screen.extract` | 提取屏幕文字 | `SCREEN` | `COPY_TEXT` | false |
| `screen.translate` | 翻译当前屏幕 | `SCREEN` | `TRANSLATE_CARD` | false |
| `screen.what` | 这是什么 | `SCREEN` | `TEXT_CARD` | true |
| `clip.summarize` | 总结剪贴板 | `CLIP` | `TEXT_CARD` | false |
| `clip.polish` | 润色/纠错 | `CLIP` | `TEXT_CARD` | false |
| `image.ocr` | 图片取字 | `IMAGE` | `COPY_TEXT` | true |
| `image.explain` | 图片解说 | `IMAGE` | `TEXT_CARD` | true |

公开操作：

- `p0()` / `all()`：返回不可变的 8 条任务列表。
- `find(id)` / `require(id)`：按 id 查找；查找前去除首尾空白，未知 id 显式失败。
- `bySource(source)`：按取料源分组，保持注册顺序，供二级菜单使用。
- 注册时校验 id 唯一，并强制每条模板包含 `{{text}}`，避免新增任务时出现空模板。

### 提示词模板填充

- `PromptTemplate.TEXT_PLACEHOLDER` 固定为 `{{text}}`，与设计文档 §7 一致。
- 使用 `String.replace` 做字面替换，替换全部占位符；文本中的 `$`、反斜杠等不会触发正则替换。
- `TaskRegistry.fillPrompt(QuickTask, CaptureBundle)` 使用取料文本；图片任务没有文本时以空串填充，图片仍通过 `CaptureBundle.images` 传递。
- 填入的文本不裁剪，保留原始换行与首尾空白。

### 前置失败判断

`TaskPreflight` 为纯 Java 判断，供菜单灰显、调度器和 JUnit 共用：

- `beforeStart(task, sourceAvailable, modelReady, visionSupported)`：
  1. 取料源不可用 → `SOURCE_UNAVAILABLE`，按 source 给出明确文案（如“开启无障碍以读取屏幕”“尚未选择图片”）。
  2. 模型未配置 → `MODEL_UNAVAILABLE`（“未配置模型”）。
  3. `needsVision=true` 但模型不支持视觉 → `VISION_UNSUPPORTED`（“当前模型不支持读图”）。
- `afterCapture(task, bundle)`：
  1. `needsVision=false` 且文本为空 → `EMPTY_TEXT`（“没有可处理的内容”），即使 bundle 带图片也失败，符合设计文档 §7。
  2. `needsVision=true` 且没有图片 → `MISSING_IMAGE`；屏幕任务提示“当前页面无法读取”，图片任务提示“尚未选择图片”。
- 成功结果为 `Result.ok()`；失败结果包含稳定的 `Failure` 枚举与可直接用于 UI 的文案。

## 与设计文档的差异

1. 设计文档 §4/§12 只列出 `TaskRegistry`，未列出模板渲染和前置检查辅助类。本实现新增顶层纯 Java `PromptTemplate` 与 `TaskPreflight`，便于 QA04 调度器和后续 UI 直接复用，不改变 `QuickTask` 数据契约。
2. 设计文档的 `ModelChannel` 接口只有 `ready()`，没有视觉能力声明。`TaskPreflight.beforeStart(...)` 因此接收独立的 `visionSupported` 布尔值；QA03 接入模型通道后由调用方映射，不能把“未配置模型”或“不支持视觉”静默当作可用。
3. 设计文档未规定 8 条提示词的具体措辞，本实现按各任务的输出要求编写中文模板；所有任务统一保留 `{{text}}` 占位符，图片内容由 `PromptImage` 单独附加。
4. 设计文档要求按取料源分组展示；本任务只提供 `bySource(...)` 数据能力，菜单视图与灰显交互属于 QA05。
5. `QuickTask.title` 按设计文档中文标题写入。当前字符串资源已有对应翻译键，但 `QuickTask` 契约没有资源 id 字段，运行时本地化留待 UI 层映射，不在本任务改动数据声明。
